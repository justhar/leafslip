<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client ↔ API | Untrusted chat input; token logging must not leak user context |
| API ↔ Google AI | API keys must be protected; token counts logged locally, not sent to third parties |
| App ↔ Database | Token logs stored in user-scoped rows; queries filtered by userId |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-OPT-02 | Information Disclosure | AI context in logs | mitigate | Token logs store count + cost only; NO user context, message content, or personal data. Separate concerns: logs contain metadata only. |
| T-OPT-03 | Denial of Service | Logging overhead | mitigate | Async logging wrapper (try-catch from Wave 1); failed logging does not crash AI action. If DB unavailable, fallback to console warning. |
| T-OPT-04 | Tampering | token_usage_log entries | mitigate | Enforce `userId` foreign key; token records immutable (no UPDATE supported in this phase). Role-based queries in Phase 2. |

</threat_model>
