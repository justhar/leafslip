## Existing Schema Context

From `db/schema.ts`, current tables:
- `users`: Core user/account data (UUID id)
- `accounts`: OAuth/auth provider data
- `sessions`: Session management
- `receipts`: Scanned receipt records
- `receiptItems`: Line items from receipts
- `products`: Product catalog
- `aiInsights`: Cached AI-generated insights

All user-scoped tables reference `users.id` with UUID type and `onDelete: 'cascade'`.

## New Tables Required

### token_usage_log (Per OPT-01, Phase 1 instrumentation backend)
- Minimal schema for metrics
- Direct cost calculation (no denormalization)
- FK to users (scoped to user)
- Indexed by userId + createdAt for efficient time-series queries

### surplus_listings (Per MARKET-01, surplus marketplace)
- Track inventory offered for discount/surplus disposal
- FK to products (optional; listings can be one-off items)
- FK to users (MSME owner)
- Status tracking: active, expired, sold_out, archived
- Expiry auto-cleanup support

### surplus_reservations (Per GUEST-02, guest reservations)
- Appointment/reservation bookings on surplus items
- FK to surplus_listings
- Guest info (name, email, phone) — optional email for v1
- Status tracking: pending, confirmed, completed, cancelled, expired
- Expiry support for auto-cancellation

- Drizzle ORM

```typescript
// Token usage instrumentation table
export const tokenUsageLog = pgTable("token_usage_log", {
  id: serial("id").primaryKey(),
  userId: uuid("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  callSite: varchar("call_site", { length: 50 }).notNull(), // 'chat' | 'ocr' | 'product_insights' | 'dashboard'
  inputTokens: integer("input_tokens").notNull(),
  outputTokens: integer("output_tokens").notNull(),
  totalTokens: integer("total_tokens").notNull(),
  model: varchar("model", { length: 50 }).notNull(), // 'gemini-2.5-flash'
  costUSD: decimal("cost_usd", { precision: 8, scale: 6 }).notNull(),
  createdAt: timestamp("created_at").defaultNow(),
});

export const tokenUsageLogIndex = index().on(tokenUsageLog.userId, tokenUsageLog.createdAt);

// Surplus listings table
export const surplusListings = pgTable("surplus_listings", {
  id: serial("id").primaryKey(),
  userId: uuid("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  productId: integer("product_id").references(() => products.id, { onDelete: "set null" }),
  name: varchar("name", { length: 255 }).notNull(),
  description: text("description"),
  quantity: integer("quantity").notNull().default(1),
  originalPrice: decimal("original_price", { precision: 10, scale: 2 }).notNull(),
  salePrice: decimal("sale_price", { precision: 10, scale: 2 }).notNull(),
  expiresAt: timestamp("expires_at").notNull(),
  status: varchar("status", { length: 20 }).notNull().default("active"),
  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
});

export const surplusListingsUserIndex = index().on(surplusListings.userId);
export const surplusListingsStatusIndex = index().on(surplusListings.status);

// Surplus reservations table
export const surplusReservations = pgTable("surplus_reservations", {
  id: serial("id").primaryKey(),
  listingId: integer("listing_id").notNull().references(() => surplusListings.id, { onDelete: "cascade" }),
  guestName: varchar("guest_name", { length: 255 }).notNull(),
  guestEmail: varchar("guest_email", { length: 255 }),
  guestPhone: varchar("guest_phone", { length: 20 }),
  quantity: integer("quantity").notNull().default(1),
  reservationDate: date("reservation_date").notNull(),
  expiresAt: timestamp("expires_at").notNull(),
  status: varchar("status", { length: 20 }).notNull().default("pending"),
  notes: text("notes"),
  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
});

export const surplusReservationsListingIndex = index().on(surplusReservations.listingId);
export const surplusReservationsStatusIndex = index().on(surplusReservations.status);
```

Key constraints:
- All foreign keys use `onDelete: "cascade"` for user-scoped cleanup
- `products` reference on surplusListings uses `onDelete: "set null"` (listing survives if product deleted)
- Status columns have `.notNull().default()` to prevent null states
- Decimal precision for prices (10,2) and costs (8,6)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App ↔ Database | Token logs stored in user-scoped rows; token records immutable (no UPDATE in this phase). Surplus listings/reservations tied to userId (MSME owner). |
| Schema ↔ Migration | Migration files are generated (not hand-written); version-controlled in drizzle/. Schema applied via Phase 2 deployment pipeline. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-OPT-01 | Tampering | token_usage_log table | mitigate | Enforce `userId` foreign key; token records immutable once written (no UPDATE). Role-based queries (users see only their logs). Phase 2 adds query-time filtering. |
| T-MARKET-01 | Tampering | surplus_listings table | mitigate | Enforce userId foreign key; users can only CRUD their own listings. Phase 3 API routes will validate ownership before write. |
| T-GUEST-01 | Spoofing | surplus_reservations (guest identity) | mitigate | Guest name/email/phone stored but not used for auth. Phase 4 can add optional email verification link. Accept spoofing risk in v1 (low-value spam target). |
| T-DB-01 | Elevation of Privilege | Schema access | mitigate | Drizzle migrations run with Neon API credentials (environment-protected). Local dev uses `db:push` which prompts confirmation. Staging/Prod use CD pipeline with secret mgmt. |
